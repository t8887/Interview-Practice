Design Patterns — Architecture-First Guide

This folder contains an architecture-first, interview-focused study guide for design patterns across Backend, Frontend, Distributed Systems, Cloud, and Node.js systems. Material is optimized for engineers with 3+ years experience preparing for product-company interviews and production architecture decisions.

Contents
- `fundamentals/` — core principles (SOLID, coupling/cohesion, composition, anti-patterns)
- `creational/`, `structural/`, `behavioral/` — classical patterns with architecture context
- `architecture-patterns/` — system-level patterns (microservices, hexagonal, CQRS, saga)
- `distributed-systems/` — reliability, consistency, resiliency patterns
- `frontend-patterns/` — React and SPA-specific patterns
- `nodejs-patterns/` — Node.js runtime patterns and pitfalls
- `cloud-patterns/` — AWS and serverless patterns, observability, scaling
- `interview/` — question bank, scenario prompts, mapping to system design
- `code-examples/` — small, runnable JS/TS/Node examples

How to use
- Follow the suggested study order in `todo.md`.
- Read pattern pages with architecture sections first, then study code examples.
- Use `interview/` to rehearse answers and scenario-driven explanations.

Design goals
- Architecture-first: each pattern shows when and why to choose it in system design.
- Interview-ready: succinct explanation, trade-offs, common pitfalls, trick questions.
- Production-ready: scaling, observability, memory and performance concerns.
