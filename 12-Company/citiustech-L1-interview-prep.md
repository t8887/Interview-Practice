- [ ] Review all sections 4-12 (self-intro, resume, technical topics)

- [ ] Prepare examples of your AWS usage: Lambda, SQS, SNS, S3, RDS, DynamoDB, etc.
- [ ] Review FHIR basics (if time) — not required but impresses healthcare-focused companies

### Morning of Interview
- [ ] Wake up 2 hours before first round
- [ ] Light breakfast, water nearby (stay hydrated)
- [ ] Wear business casual (visible on video from shoulders up) — CitiusTech is modern, no strict formal dress
- [ ] Set up in a quiet room with good lighting and a neutral background
- [ ] Close Slack, email, other notifications — no distractions
- [ ] Join the call 10 minutes early — log in and do a quick audio/video check
- [ ] Have a notebook and pen beside you

### During the Interview
- [ ] **Speak clearly and slowly** — especially names of technologies and company names
- [ ] **Listen carefully to the entire question** before answering — don't interrupt
- [ ] **Clarify ambiguous requirements** — ask 2-3 clarifying questions for system design problems
- [ ] **Think out loud** — interviewers want to see your thought process, not just the answer
- [ ] **If you get stuck:** Say "Let me think for a moment," take 10-15 seconds, then explain your approach
- [ ] **For coding:** Write clean code, add comments, test edge cases, discuss time/space complexity
- [ ] **For system design:** Draw diagrams (use ASCII if needed), discuss trade-offs, ask about scale

### After the Interview
- [ ] Thank the interviewer and ask when you can expect feedback
- [ ] Write down feedback, questions asked, any topics you struggled with (for next round prep)
- [ ] Email your contact within 1-2 hours thanking them for the opportunity, reiterating interest
- [ ] **Do NOT follow up aggressively** — CitiusTech moves fast; you'll hear within 5-7 business days

## 6. Round 1 – Technical Round: JavaScript & TypeScript

### Core Topics (L1 Level Expected)

#### 1. JavaScript Fundamentals
**Must know:**

- Closures and lexical scoping
- Prototypes and prototype chain
- this binding (call, apply, bind)
- Event loop and async behavior
- Callback, promises, async/await

**Expected difficulty:** Easy to Medium

**Sample questions:**
1. **Hoisting:** What's the output?
   ```javascript
   console.log(a);
   var a = 5;
   console.log(a);
   ```
   Answer: `undefined`, then `5` (var is hoisted as declaration but not initialization)

2. **Closures:** Create a counter function that increments/decrements
   ```javascript
   function createCounter() {
     let count = 0;
     return {
       increment: () => ++count,
       decrement: () => --count,
       getCount: () => count
     };
   }
   const counter = createCounter();
   console.log(counter.increment()); // 1
   console.log(counter.increment()); // 2
   ```

3. **Promise chaining vs async/await:**
   ```javascript
   // Promise chaining
   function fetchUser(id) {
     return fetch(`/api/users/${id}`)
       .then(res => res.json())
       .catch(err => console.error('Error:', err));
   }
   
   // Async/await (preferred)
   async function fetchUser(id) {
     try {
       const res = await fetch(`/api/users/${id}`);
       return res.json();
     } catch (err) {
       console.error('Error:', err);
     }
   }
   ```

4. **this binding:**
   ```javascript
   const obj = {
     name: 'Onkar',
     greet: function() {
       console.log(this.name);
     },
     greetArrow: () => {
       console.log(this.name); // undefined (no 'this' binding in arrow functions)
     }
   };
   obj.greet(); // 'Onkar'
   obj.greetArrow(); // undefined
   ```

**Must know:**
- Basic types (string, number, boolean, any, unknown, never)
- Interfaces vs types
- Generics (function generics, class generics)
- Union and intersection types
- Type guards and type narrowing
- Utility types (Partial, Readonly, Record, Pick, Omit)

**Expected difficulty:** Easy to Medium

**Sample questions:**
1. **Generics for a reusable API response:**
   ```typescript
   interface ApiResponse<T> {
     data: T;
     status: number;
     message: string;
   }
   
   function handleResponse<T>(response: ApiResponse<T>): T {
     return response.data;
   }
   
   // Usage
   interface User {
     id: number;
     name: string;
   }
   
   const userResponse: ApiResponse<User> = {
     data: { id: 1, name: 'Onkar' },

   };

   ```

2. **Type guards:**
   ```typescript
   type Employee = { id: number; name: string; department: string };
   type Contractor = { id: number; name: string; agency: string };
   
   function processWorker(worker: Employee | Contractor) {
     if ('department' in worker) {
       console.log(`Employee in ${worker.department}`);
     } else {
       console.log(`Contractor from ${worker.agency}`);
     }
   }
   ```

#### 3. Advanced Patterns
**Nice to know:**
- Design patterns: Factory, Singleton, Observer
- Debounce/Throttle implementations
- Memoization

**Expected difficulty:** Medium

**Sample question:**
1. **Debounce function:**
   ```typescript
   function debounce<T extends (...args: any[]) => any>(
     fn: T,
     delay: number
   ): (...args: Parameters<T>) => void {
     let timeoutId: NodeJS.Timeout;
     return (...args: Parameters<T>) => {
       clearTimeout(timeoutId);
       timeoutId = setTimeout(() => fn(...args), delay);
     };
   }
   
   // Usage: search field that debounces API calls
   const debouncedSearch = debounce((query: string) => {
     console.log('Searching for:', query);
   }, 300);
   ```

**Sample questions:**

1. **Event loop:** Explain the output order
   ```javascript
   console.log('1');
   
   setTimeout(() => console.log('2'), 0);
   
   Promise.resolve().then(() => console.log('3'));
   
   console.log('4');
   
   // Output: 1, 4, 3, 2
   // Explanation: Sync → Microtask (Promise) → Macrotask (setTimeout)
   ```

2. **Streams for large file handling:**
   ```javascript
   // Without streams: loads entire file into memory (bad for large files)
   const fs = require('fs');
   const data = fs.readFileSync('large-file.txt', 'utf8'); // Can crash if file is 1GB+
   
   // With streams: processes in chunks (good for large files)
   fs.createReadStream('large-file.txt', { highWaterMark: 64 * 1024 })
     .pipe(transform)
     .pipe(output);
   ```

3. **Express middleware chain:**
   ```javascript
   const express = require('express');
   const app = express();
   
   // Middleware executes in order
   app.use((req, res, next) => {
     console.log('Auth middleware');
     req.user = { id: 1, name: 'Onkar' };
     next(); // pass control to next middleware
   });
   
   app.use((req, res, next) => {
     console.log('Logging middleware');
     next();
   });
   
   app.get('/profile', (req, res) => {
     res.json(req.user); // user is available from auth middleware
   });
   ```

#### 2. Backend Architecture

**Expected difficulty:** Medium

**Sample questions:**

1. **RESTful API design:** Implement a basic user CRUD endpoint
   ```javascript
   const express = require('express');
   const router = express.Router();
   
   // GET /users - List users
   router.get('/', async (req, res) => {
     try {
       const users = await User.find().limit(10);
       res.json({ data: users, status: 200 });
     } catch (err) {
       res.status(500).json({ error: err.message });
     }
   });
   
   // POST /users - Create user
   router.post('/', async (req, res) => {
     try {
       const user = new User(req.body);
       await user.save();
       res.status(201).json({ data: user, status: 201 });
     } catch (err) {
       res.status(400).json({ error: err.message });
     }
   });
   
   // GET /users/:id - Get specific user
   router.get('/:id', async (req, res) => {
     try {
       const user = await User.findById(req.params.id);
       if (!user) return res.status(404).json({ error: 'Not found' });
       res.json({ data: user, status: 200 });
     } catch (err) {
       res.status(500).json({ error: err.message });
     }
   });
   
   // PUT /users/:id - Update user
   router.put('/:id', async (req, res) => {
     try {
       const user = await User.findByIdAndUpdate(req.params.id, req.body, { new: true });
       res.json({ data: user, status: 200 });
     } catch (err) {
       res.status(500).json({ error: err.message });
     }
   });
   
   // DELETE /users/:id - Delete user
   router.delete('/:id', async (req, res) => {
     try {
       await User.findByIdAndDelete(req.params.id);
       res.status(204).send();
     } catch (err) {
       res.status(500).json({ error: err.message });
     }
   });
   ```

2. **JWT authentication middleware:**

#### Problem 1: Valid Parentheses

```javascript
/**
 * Given a string s containing parentheses, determine if it's valid.
 * Rules: () [] {} - each type must match, must be in correct order
 * Example: "()" → true, "([)]" → false
 */
function isValid(s) {
  const stack = [];
  const pairs = { ')': '(', ']': '[', '}': '{' };
  
  for (const char of s) {
    if (char === '(' || char === '[' || char === '{') {
      stack.push(char);
    } else if (char === ')' || char === ']' || char === '}') {
      if (stack.pop() !== pairs[char]) return false;
    }
  }
  
  return stack.length === 0;
}

// Time: O(n), Space: O(n)
```

#### Problem 2: Merge Two Sorted Lists

```javascript
/**
 * Merge two sorted linked lists
 */
function mergeTwoLists(list1, list2) {
  const dummy = new ListNode(0);
  let current = dummy;
  
  while (list1 && list2) {
    if (list1.val <= list2.val) {
      current.next = list1;
      list1 = list1.next;
    } else {
      current.next = list2;
      list2 = list2.next;
    }
    current = current.next;
  }
  
  // Attach remaining nodes
  current.next = list1 || list2;
  return dummy.next;
}

// Time: O(n + m), Space: O(1)
```

#### Problem 3: Two Sum

```javascript
/**
 * Find two numbers that add up to target
 * Example: nums = [2,7,11,15], target = 9 → [0,1]
 */
function twoSum(nums, target) {
  const seen = {};
  
  for (let i = 0; i < nums.length; i++) {
    const complement = target - nums[i];
    if (complement in seen) {
      return [seen[complement], i];
    }
    seen[nums[i]] = i;
  }
  
  return [];
}

// Time: O(n), Space: O(n)
```

## 17. Quick Revision Cheatsheet

### JavaScript/TypeScript (30 sec each)

**Closures:** Variables from outer scope accessible in inner function
**Promises:** `.then()` for success, `.catch()` for error, `async/await` is cleaner
**Event loop:** Sync code → Microtask (Promise) → Macrotask (setTimeout)
**Generics:** `<T>` allows type-safe reusable functions
**this binding:** `function` has dynamic this, `=>` has lexical this

### Node.js (30 sec each)

**Middleware:** Execute in order, `next()` passes control
**Streams:** Process large files in chunks instead of loading entirely
**Async patterns:** Use `Promise.all()` for parallel, `for await...of` for sequential
**Error handling:** Try/catch for sync, `.catch()` for promises
**Connection pooling:** Reuse DB connections, don't create per request

### React (30 sec each)

**Hooks:** `useState` (state), `useEffect` (side effects), `useContext` (global state)
**Component composition:** Break UI into small, reusable components
**Performance:** `React.memo` (prevent re-renders), `useCallback` (memoize functions), `useMemo` (memoize values)
**Testing:** Use React Testing Library, test user behavior not implementation

### AWS (30 sec each)

**Lambda:** Serverless, scalable, max 15 min execution, cold start latency
**S3:** Object storage, use lifecycle policies to save cost
**RDS:** Relational DB, use read replicas for read-heavy workloads
**API Gateway:** Route requests, handle auth, throttling
**VPC:** Network isolation, security groups control access

### Databases (30 sec each)

**Indexes:** Speed up queries, composite index for multi-column filters
**Transactions:** ACID properties, MySQL good for financial data
**MongoDB:** Document DB, flexible schema, good for flexible data
**Redis:** In-memory cache, session storage, pub/sub
**Replication:** Primary-replica for HA, replica-lag is a concern

### System Design (30 sec each)

**Load balancing:** Distribute traffic across servers
**Caching:** Redis for hot data, reduces DB load
**Queue:** SQS/Kafka for async processing, decouples services
**CDN:** Serve static content from edge servers
**Monitoring:** CloudWatch, DataDog, alerts on critical metrics
